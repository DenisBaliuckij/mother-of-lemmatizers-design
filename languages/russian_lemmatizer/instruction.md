# Russian Lemmatizer (Rule-based + Python Analysis)

Этот модуль реализует **Анализ (форма → лемма)** для русского языка (Уровень A по архитектуре «Мать лемматизаторов»). 
Модуль работает независимо: он не использует движок `lingua-rules` и файлы `.lp` для анализа, а строит лексикон напрямую из онтологии и словаря Apertium.

## Результаты оценки

- **Кросс-валидация (5-fold)** на development-наборе (1000 токенов): **92.8%** точности (на уровне токенов), 86.5% (на уровне предложений).
- **Holdout (слепой тест)** на 300 отложенных токенах: **92.0%** точности (276 из 300 верно), 88.4% (на уровне предложений).
- **По источникам:** словарные совпадения (Apertium) дают 97.5% точности, правила окончаний — 100%.

## Устройство папки

* `russian_lemmatizer.py` — основной класс `RussianLemmatizer` (Артефакт B). Реализует логику анализа: нормализация, поиск в словаре, отсечение окончаний, ранжирование омонимов и обработку композитов (аналитических форм).
* `run_cv.py` — скрипт для запуска 5-fold кросс-валидации.
* `run_holdout.py` — скрипт для оценки качества на отложенной выборке (`russian-holdout.yaml`).
* `OntoRussian.json` — онтология русского языка (источник правил, исключений и конфигураций).
* `apertium-rus.rus(1).dix` — морфологический словарь Apertium (127 000+ словарных статей). Используется как основной лексикон.
* `russian-development.yaml` — development-набор (1000 токенов из SynTagRus).
* `russian-holdout.yaml` — отложенный тестовый набор (300 токенов).
* `russian-evaluation-results.csv` — детальный лог с ошибками (колонки: `form`, `expected`, `actual`, `UPOS`, `status`, `reason`).

## Как запустить

Для работы требуется Python 3.11+ и библиотека `PyYAML`. Словарь Apertium парсится автоматически, при первом запуске создается кэш базы данных SQLite (папка `.cache/`), это может занять около 1–2 минут.

1. Установите зависимости:
   ```bash
   pip install pyyaml
   ```

2. Запустите кросс-валидацию:
   ```bash
   python run_cv.py
   ```

3. Запустите оценку на Holdout (создаст `ru-holdout-report.md` и обновит CSV):
   ```bash
   python run_holdout.py
   ```

## Как это устроено

1. **Лексикон:** при инициализации класс загружает онтологию, development-набор и XML-словарь Apertium. Для скорости словарь Apertium конвертируется в SQLite-базу (индексируется по форме и части речи).
2. **Пайплайн анализа (порядок применения):**
   - Поиск точного совпадения в development-наборе.
   - Поиск в кэше Apertium.
   - Если слова нет — применяются правила отсечения окончаний на основе известных лемм.
   - Если ничего не подошло — возвращается `ambiguous` (лемма равна исходной форме).
3. **Ранжирование омонимов:** при наличии нескольких вариантов лемм код использует эвристики (совпадение по признакам UD, наличие/отсутствие возвратного постфикса `-ся`, длина общего префикса с исходным словом).
4. **Аналитические формы:** в методе `lemmatize_sentence` распознаются конструкции «буду + инфинитив», «глагол + бы» и т.д.

## Ограничения

- Лемматизатор опирается только на онтологию (сделанную на 60% по Грамматика-80), apertium и development-набор (SynTagRus).
- Ошибки (24 из 300 в Holdout) в основном связаны с омонимией, редкими словами и словами, которых нет в словаре Apertium (статус `ambiguous`).
