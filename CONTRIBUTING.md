# Как вносить изменения

## Порядок работы

1. Создайте ветку от `main` (например, `ru-03-open-set-threshold`).
2. Измените нужные разделы в `ru/` и/или `en/`.
3. Откройте pull request и заполните шаблон: какой раздел, что изменилось и почему. В еженедельную сводку попадает только заголовок pull request'а, поэтому сформулируйте его содержательно.
4. Обсудите изменения в комментариях к pull request'у — к нему целиком или к отдельным строкам. Для слияния нужно одно одобрение (Approve) от другого участника.
5. После одобрения pull request сливается методом squash, ветка удаляется автоматически.

Свои изменения нельзя одобрить самостоятельно, а в `main` нельзя пушить напрямую — это касается всех, включая владельца репозитория.

## Две языковые версии

Русская (`ru/`) и английская (`en/`) версии описывают одно и то же, файлы с одинаковыми номерами соответствуют друг другу.

- Если можете, вносите правку сразу в обе версии.
- Если правите только одну, напишите в описании pull request'а «нужен перевод» — перевод можно сделать отдельным pull request'ом.

## Что где править

- **Текст раздела** — в файле `ru/NN-….md` или `en/NN-….md`. Каждый файл начинается с заголовка первого уровня (`# …`); подразделы — `##` и `###`.
- **Схемы** — в блоках ```` ```mermaid ```` внутри раздела. Перенос строки в подписи узла — `<br/>`. Проверить, как схема рисуется, можно во вкладке Preview редактора GitHub или на [mermaid.live](https://mermaid.live).
- **Новый раздел** — новый файл со следующим свободным номером в обеих папках и строка в таблице разделов в [README.md](README.md).
- **Литература** — в разделе `13-references.md`; ссылки в тексте давайте на работы из этого списка.

Папку `original/` не редактируйте: это снимок первого черновика.

## Спорные места

Если правка меняет суть решения (а не формулировку), сначала откройте Issue по шаблону «Замечание к разделу» или тему в Discussions и сошлитесь на неё в pull request'е — так обсуждение не потеряется в закрытом PR.
